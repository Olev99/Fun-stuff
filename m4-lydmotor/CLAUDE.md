# M4 Lydmotor: rules for working in this folder

This folder is a separate app from Zoomies. The Zoomies rules in the root `CLAUDE.md` (stamping, `run.mjs`, the `kart-*` agents, model routing) do not apply here. Nothing in `m4-lydmotor/` may touch `zoomies/`, and nothing in `zoomies/` may depend on this folder. The root rules on branches and pull requests, and on keeping model names out of repo files, commit messages and PR text, still apply.

## What it is

A single-page web app that makes an electric car (the owner's BMW i4 M50) sound like a BMW M4 CSL (2023, G82, S58 3.0 L twin-turbo inline-6, 8-speed automatic, 7,200 rpm limiter). It runs in iPhone Safari, plays through the car speakers over CarPlay or Bluetooth, and is driven by real driving: GPS speed plus the phone's accelerometer. It is a hobby project and not a product.

The car is data: besides the M4 CSL (the default), the owner can pick an Aston Martin Vanquish S, an Aston Martin V12 Vantage S, a Ferrari F12berlinetta, a Porsche 911 GT3 (991.2), a Lexus LFA or a Porsche Carrera GT under Innstillinger (see "Car profiles"). The app title is generic ("Lydmotor"); the folder keeps its old name.

Published page: https://olev99.github.io/Fun-stuff/m4-lydmotor/ (GitHub Pages serves `main`, so a push to `main` updates it).
A private artifact with the same page exists for quick sound tests (test mode and the manual tunnel button only, because the artifact sandbox blocks GPS and motion): https://claude.ai/artifact/EcoBDqRzkNApNsuaDQu55K

## Owner's priorities (keep to these)

- **Realism of an M4 CSL, as good as it can be made.** The owner has said the first versions did not sound realistic enough. Judge changes by ear-relevant facts (pitch tied to rpm, firing frequency rpm/20 Hz, rasp, load behaviour) and by the numeric checks in `src/test.js`. Nobody can listen in the cloud sandbox, so say clearly what was verified numerically and what only the owner's ear can judge.
- **Gear shifts matter most.** Upshifts under load (ignition cut, crackle, bang), lift-off and overrun (fuel cut, burble, pops), and rev-matched downshifts (the blip) must be clearly audible. When the owner reports something wrong, start there.
- **Tunnel acoustics:** a convolution reverb on a wet send, switched by a manual button and by GPS loss; an optional map lookup is off by default because it sends the position to OpenStreetMap.
- **Minimum latency.** The DSP runs in an AudioWorklet with 128-sample quanta, driven by `latencyHint: 'interactive'`. Do not add main-thread work to the audio path. Bluetooth and CarPlay buffering is outside our control.
- **Norwegian (bokmål) UI text.** Phone first, large controls, nothing to touch while driving: the start screen starts audio and sensors in one tap.
- **Sound must be our own.** No recorded or ripped engine samples from games, videos or other copyrighted sources. Synthesis, or recordings the owner makes himself.

## Layout

- `index.html`: the built single file that GitHub Pages serves. Do not edit it by hand.
- `src/template.html`: markup and styles. `src/main.js`: page script (UI, sensors, GPS and motion fusion, tunnel detection, settings). `src/engine.js`: class `EngineCore`, the whole sound and drivetrain model.
- `src/build.py`: `python3 m4-lydmotor/src/build.py` inlines `engine.js`, `main.js` and the small logo (`icon/mark.svg`, at both `/*MARK*/` places) into `template.html` and writes `m4-lydmotor/index.html`. Rebuild and commit `index.html` with every source change.
- App icon and install files (siblings of `index.html`, linked with relative URLs, not inlined; the single-file artifact simply lacks them): `icon/icon.svg` (source, 1024 viewBox), `apple-touch-icon.png` (180), `icon-192.png`, `icon-512.png`, `icon-maskable-512.png` (art scaled to 82 % for Android's safe circle), `favicon.png` (64), `manifest.webmanifest` (name Lydmotor, `lang` nb, standalone, any orientation, colours #07080a). Regenerate: `python3 m4-lydmotor/icon/genicon.py m4-lydmotor/icon/icon.svg` (geometry and colours of the icon), `python3 m4-lydmotor/icon/genmark.py > m4-lydmotor/icon/mark.svg` (the in-page logo; its parts are coloured by CSS classes, so it follows the car accent), then `node m4-lydmotor/icon/render.js [folder]` rasterises every PNG in headless Chrome (with a folder it also writes 1024 and 60 px proofs there). The icon is full-bleed and opaque (iOS applies its own mask) and has no text or brand marks.
- `src/sensortest.js`: `node m4-lydmotor/src/sensortest.js` loads the built page in headless Chrome over localhost, checks the test-to-drive switch, the "Rygger" status and console errors, then runs synthetic reversing drives (forward and reverse from a stop, parking, queue, noisy cruising, other GPS delays and bias; zero false reverse allowed) and a synthetic drive through the real fusion code (60 Hz accelerometer with noise and bias, GPS speed one second late): speed error and jumps at GPS fixes, 6 % up/down hills at constant speed, a phone jolt, throttle step response and noise. `NO_UI=1 node ... <old.html>` runs only the drive part against an older build (that build must export `onMotion` in `window.__m4`).
- `src/test.js`: offline Node checks. `node m4-lydmotor/src/test.js` runs them for every car (about 50 checks per car plus cross-car and output checks: spectrum, firing frequency, shift trajectories, pops, limiter, tunnel tail, clipping, CPU cost); `node m4-lydmotor/src/test.js f12` runs one car; `node m4-lydmotor/src/test.js demo [car] [output]` renders a demo drive to WAV (for example `demo f12 i4hk`). Thresholds in rpm scale with the car's redline (×redline/7200), so the M4 keeps its original numbers.
- `src/sw.js`: source of the service worker; `build.py` writes `m4-lydmotor/sw.js` from it (see "Offline: service worker"). `src/loganalyze.js`: `node m4-lydmotor/src/loganalyze.js <log.json>` analyses a drive log (see "Drive log").
- `sensortest.js` also checks the app features below (Media Session, road-noise volume and its peak cap, settings export/import, per-car settings, migration, unknown car ids, gauge frame rate, service worker offline start and updates, drive log and `loganalyze.js`). It serves the page's folder statically (so `sw.js`, the manifest and icons load); `SHOTS=<folder>` saves screenshots of the new UI pieces (393×852 and 852×393), `LOGOUT=<prefix>` writes the synthetic drive logs (`<prefix>-1000.json`, `<prefix>-1500.json`) as samples for `loganalyze.js`. It grants the `accelerometer`/`gyroscope` permissions (current headless Chrome otherwise denies motion, which now shows the retry button).

## Constraints that bite

- `EngineCore` is sent to the AudioWorklet as text with `EngineCore.toString()`, so the class must be fully self-contained (no outside references). The same class runs on the main thread as a ScriptProcessor fallback.
- The worklet loads from a blob URL; that fails on `file://`, so test over `http://localhost`.
- iOS Safari: audio and sensors stop if the page is backgrounded or the screen locks (wake lock is used and re-acquired); the silent switch mutes Web Audio unless the audio session is set to playback and a silent looping audio element runs (both are in place); motion permission needs a user gesture.
- GPS and motion only work on an https origin, not inside the artifact sandbox.
- GPS speed arrives about once per second and about a second late. The accelerometer is the only fast signal, so throttle and braking are inferred from it. In the i4, lifting off the pedal brakes by regeneration, which the model treats as engine braking.
- BMW CarData is not usable for this (event-driven, low request limits, no speed or pedal data).

## Known open points

- Nothing has been tested on a real iPhone or in the car: latency, wake lock, silent switch, sensor permissions, real tunnel behaviour, CPU on the phone.
- The design was only checked in headless Chrome screenshots (393×852, 360×640, 852×393): not the SF font rendering, safe areas and the black-translucent status bar in a home-screen app, the home-screen icon itself, readability of the dark UI in sunlight, or the battery cost of the 30 fps gauge on an iPhone.
- The waveform is peaky (crest factor about 14 dB at full throttle) and may sound harsher than a cabin recording; check by ear.
- An early version let the half order dominate (a three-cylinder-like beat). It is fixed in the model, but confirm by ear that the six sounds smooth.
- Gear ratios and final drive (5.000/3.200/2.143/1.720/1.313/1.000/0.823/0.640, 3.154) come from one spec site; a second site listed a different set that was not checked against a BMW source.
- Sensor fusion (main.js) is only checked with the synthetic drive in `sensortest.js`; the real car may differ:
  - GPS delay is assumed to be 1.0 s (`GPS_LAG`). The real iPhone delay is not measured; if speed still lags or overshoots at each fix, tune it.
  - Slope compensation reads the grade from the OS gravity vector along the learned forward axis (bounded to ±10 %, slow baseline, only when the OS separates gravity). Downhill at constant speed now reads as lift-off (overrun sound); uphill as more throttle. Braking downhill at constant speed is not detected as braking. Unverified in a real car.
  - The jolt guard freezes throttle and brake for 0.7 s when rotation exceeds 80 °/s. Normal cornering should stay well below that (a 90° turn in 2 s is 45 °/s), but check that it never freezes in normal driving, and that lifting the phone out of the holder does not cause kick-downs.
  - The saved calibration (`m4cal` in localStorage, 14 days) is discarded when the phone's gravity direction differs by more than about 25° for 3 s. Rotating the phone in the plane perpendicular to gravity is not detected; the owner then has to press Nullstill kalibrering.
  - The throttle path is faster (accelerometer filter 35 ms, throttle 30 ms up and 80 ms down); in the synthetic drive, noise rose from 0.013 to 0.020 (std). Real holder vibration may need a longer filter.
- Reversing (`dirFix` in main.js) is decided only when the car moves off from a standstill: the acceleration along the learned forward axis is integrated from the last quiet moment while stopped (0.5-1.6 s back, so it tolerates a GPS delay other than 1 s) to the first GPS fix at 0.8 m/s or more. Positive is forward, negative is reverse; an unclear result waits for the next fix and plays forward. Reverse is only set below 4 m/s, after calibration, with no phone jolt in the window, and only if the sensors say the car is still rolling backwards. It ends at a stop (GPS or the sensor integral), above 8 m/s, when sensor and GPS acceleration agree in sign, or after 40 s. In reverse the engine gets speed x0.8 capped at 3.4 m/s and throttle capped at 0.5 (stays in 1st, under about 2,000 rpm), the status line shows "Rygger" and the gauge "R". The forward axis and bias are not learned in reverse or before the direction is decided, and the axis only above 5 m/s. iPhone speed -1 at a stop counts as a standstill. Synthetic results (`sensortest.js`): no false reverse while driving forward in any case (also checked over ten noise seeds), 8 of 9 calibrated reverses found, 2-3 s after the car starts rolling; a short reverse with a 1.6 s GPS delay can be missed. Only a real car can confirm: the real GPS delay and how often iOS reports speed 0 or -1 at a stop, holder vibration and brake-release pitch at pull-away, creeping under 0.8 m/s (never detected), and how the R sound feels. GPS heading and the compass were not used (heading is -1 or unreliable at parking speeds).
- The audio watchdog (resume every 1 s, then every 5 s after five failures; also restarts the silent keep-alive track) and the wake-lock re-request were only exercised in desktop Chrome (suspend/resume). iOS call and Siri interruptions and the `interrupted` state need a real iPhone.
- Exhaust flap (engine.js): Sport is open in gears 1-3 while moving, above about 55 % load or 4,500 rpm, otherwise 0.2; it opens in 30 ms and closes over 0.4 s. Sport idle is a little quieter than before by design. Judge by ear whether cruising in Sport (flap mostly closed) is too tame.
- The live OpenStreetMap request (optional tunnel lookup) was never exercised; only the matching code was tested with a synthetic tunnel.
- Throttle at steady speed (main.js): the estimate adds 0.04 before the 0.8 power, so cruising reads as about 0.10-0.15 instead of 0.04-0.07. Without it, cruise sat on the engine's 0.05 lift threshold and sensor noise made the V12s hunt 2<->3 in Sport and Bane (14-35 shifts per 30 s in a synthetic cruise); with it, 0 shifts per 30 s for every car and mode at 20-110 km/h with throttle noise of std 0.02 (as in `sensortest.js`). Side effects: gentle deceleration between -0.35 and about -0.17 m/s² now reads as light throttle instead of lift-off (lift-off needs i4 regen stronger than 0.35 m/s²), and at 50 km/h the M4 now cruises one gear higher in Sport (before, it was treated as lifted). Check in the car that light lift-offs still give overrun.
- Gear hunting under much noisier throttle (holder vibration) is now handled in the engine as well: the lift state needs the throttle under 0.05 for 0.15 s and ends as soon as it rises above 0.08 (used for lift-off overrun and its pop, fuel cut, the coast downshift offset and the lift upshift hold), and part-throttle shift points use max(throttle, slow throttle) for upshifts and min(throttle, slow throttle) for downshifts (the existing 0.25 s filter), so short peaks and dips do not shift; steady throttle gives the old points. `test.js` checks noisy throttle (low-passed 30 ms, mean 0.12/0.15, std 0.05/0.08) at 30-110 km/h in every mode for every car: at most 1 shift per 30 s (now 0; before up to 35 for the V12s and V10s, in every mode). M4 changes: lift-off overrun 21 ms later from full throttle (131 -> 152 ms after the lift), 37-51 ms later from part throttle; upshifts while easing off 30-35 ms later. A real lift still gives overrun within 0.2 s and the first pop within 0.25 s (checked for every car). Check in the car that quick lift-and-reapply (under 0.15 s) feels right: it no longer gives overrun.
- The output limiter's envelope never falls below the current sample's peak (`limEnv = max(pk, limEnv × release)`), so the ceiling is exact; the i4 HK check requires peaks at most fround(ceiling). Before, the release could leave up to 0.03 % overshoot (0.53015 against 0.53). The fixed regression renders were bit-identical; in 20 worst-case drives per car the old code overshot on 0-3 of 19.7 million samples, and the M4 with `std` differs on 108 of 39.4 million samples (0.0003 %) by at most 1.5e-4.
- The exhaust-mode check compares 2-5 kHz shares in a window that, in Komfort, lands on the first block of a soft 2>3 upshift (rpm still near the redline), so in effect it asks Bane to be raspier than that moment. The Vantage S Bane rasp (2.0) passes it with a small margin.

## Car profiles

`EngineCore.profiles()` returns one plain, JSON-cloneable object per car (`m4csl`, `vanqs`, `v12vs`, `f12`, `gt3`, `lfa`, `cgt`). The page sends the chosen one to the worklet with `msg({ k: 'profile', p })`; the engine fades out over 70 ms, applies it with `setProfile()` (which calls `reset()`: idle rpm, gear picked to suit the current speed, all filter and delay state cleared), and fades back in over 70 ms. `now: true` applies it at once (used at start). In drive mode the simulated car's speed still comes from the i4's GPS/motion fusion; the profile only decides gearing, rpm and sound.

What a profile holds: cylinder count; firing order and firing angles in crank degrees over 720 (uneven firing is supported; up to 12 cylinders); bank per cylinder and per-cylinder gain and runner delay; idle, redline and limiter (`lim`: max, on, off, paddle-deny rpm, cut period and duty, rpm dip; optional `pop` = chance of a pop per cut, default every cut, and `keep` = share of the load left during a cut, default 0); the auto-shift map `shift` as fractions of the redline (rounded to whole rpm, so the M4 gets its old numbers exactly); gear ratios, final drive, wheel radius, mass, traction (`grip`), top speed, torque table (linear between points, constant power above the last); gearbox timing `box` (hard and soft shift times per mode, manual cut, driveline shuffle, launch/converter slip, standstill speed; optional `cut` = depth of the ignition cut on a hard upshift, 1 = full cut as without the field, and `kick` = the time kickdown scales from instead of the Sport upshift time); optional `rev` = [free-rev rise rpm/s, + at full throttle, fall rpm/s] for the flywheel when the clutch slips (standstill, launch; without it the engine uses 2500/7500/2600, so the older cars are unchanged; only the two V10s set it); `turbo` on/off (off: no boost, no whoosh, blow-off or flutter, load not boost-weighted); fuel cut and idle load; overrun/burble character `ovr` and `popK`; exhaust-flap logic per mode `flap`; pipe lengths `pipe`; sound shaping `snd` (the field meanings are commented above the V12 profiles in `engine.js`); tachometer scale and names for the UI.

How to add a car (data only, no engine code):
1. Copy the closest profile in `EngineCore.profiles()` and give it a new `id`, `name`, `short`, `blurb` (Norwegian) and `tach`.
2. Set `cyl`, `fire.order` (1-based cylinder numbers) and `fire.deg` (crank angles of each firing; even firing is `720 / cyl` apart), `bank` per cylinder and `gain`/`runner` arrays of length `cyl`. Any cylinder count up to 12 works (pending-pop and buffer sizes do not depend on it; the phase step is `rpm / (120 / cyl)` per sample, so the firing line is rpm/60 × cyl/2: rpm/12 Hz for a V10).
3. Set `idle`, `redline`, `lim`, `gears`, `fd`, `wheel`, `mass`, `torque`, `vmax`, `acc100` (the published 0-100 km/h time; the test expects the simulation within -0.4/+1.0 s of it), then tune `grip` until `node m4-lydmotor/src/test.js <id>` passes the 0-100 check.
4. Pick `box` for the gearbox type (torque-converter auto, single-clutch AMT, dual clutch), `turbo`, and the sound fields. Keep idle noise floors low (`snd.rasp[5]`, `snd.mech`), because the i4 cabin is quiet.
5. Add the profile to the returned object. The picker lists it automatically. Run `node m4-lydmotor/src/test.js` (every check runs for every car) and render a demo with `node m4-lydmotor/src/test.js demo <id> i4hk`.

Example: the Ferrari 812 Superfast (`f812`) is a copy of `f12` made this way; see "Ferrari 812 Superfast and 911 GT3 RS 4.0" below.

Regression gate: the M4 profile must reproduce the pre-profile engine bit for bit, with two deliberate exceptions since: blip and kickdown rpm targets are floored at idle (a sudden drop to standstill no longer dives to the 200 rpm clamp), and a car switch while moving starts at the wheel rpm with upshifts held for 1 s. It was checked with fixed renders (idle with start, cruise, full-throttle pull with auto shifts, overrun, kickdown, limiter, tunnel on/off, braking with blips, paddles, Komfort and Bane, idle off, drive mode, lift-and-roll in auto, sudden speed drop to standstill) against references from `main` after the auto-gearbox fix. When changing shared engine code, keep M4 numbers bit-identical unless the owner asks for an M4 change.

Deliberate M4 changes since (owner approved): the 0.15 s lift filter and throttle hysteresis on part-throttle shift points (lift timing +21 to +51 ms, see "Known open points"), and the exact output limiter (0.0003 % of samples, at most 1.5e-4). The `i4hk` output gained `lp2` (10 kHz); `std` is bit-identical.

GT3 sound design (our own synthesis, no samples). The model has no boxer-specific code: a flat-six with alternating-bank firing (1-6-2-4-3-5, each bank firing every 240°) is, in this model, structurally the same as the S58's split manifold (1-5-3-6-2-4 also alternates banks), so the GT3 differs only through data. Against the M4 at the same rpm (a one-off FFT comparison, not part of `test.js`: full load, 4th gear, i4hk output) the expected and measured differences are:
- No turbo: no boost-weighted load, whoosh or blow-off, and a smaller cycle-to-cycle variation (`snd.cyc` 0.02/0.05 against 0.05/0.13). The M4's 2-5 kHz content is mostly noise between the harmonics (67-81 % of that band lies between the lines); the GT3's is mostly harmonic (23-45 % between the lines at 4,500-7,000 rpm), which should read as a hard, metallic, "mechanical" rasp rather than a turbo hiss. Done with a brighter pulse (`fc` 400 Hz + 3,400 at full load + 0.11 per rpm), a higher rasp resonance (3.6 kHz against 2.3 kHz) and more rasp with load (`rasp[6]` 1.1).
- Intake emphasis: rear engine with the intake close to the cabin, so a strong induction path (`intake[0]` 0.36, the highest of all cars; resonators at 260 and 720 Hz). - Short exhaust (`pipe.DA` 1.6 m against 4.2 m), equal-length headers (equal `SA`/`SB`, small runner spread), flap opening above about 50 % load or 5,000 rpm in Sport (`flap.s`), restrained overrun (`ovr.mode` Sport 0.7, `popK` 0.3, see "Reference-based tuning") and fast PDK shifts (`box.hardT` 80/65/45 ms, `box.cut` 0.4).
- Valvetrain tick at idle: the tick (`mech[0]` 0.007) is kept and the steady mechanical floor nearly removed (`mech[2]` 0.01), so the band above 2 kHz at idle is impulsive (95th/50th percentile of its 1 ms envelope about 13.6 dB) rather than a hiss. A-weighted 1.5-6 kHz at idle: GT3 -24.2 dB of the total, Vanquish S -23.8, F12 -22.2, V12 Vantage S -19.2, M4 -11.2 (the test requires GT3 at or below -23.9 dB).

### Reference-based tuning (V12s and GT3)

Real recordings (YouTube, mostly exterior or onboard microphones, lossy audio; measurement only, kept in the scratchpad and never in the repo or the app) of the F12, the Vanquish S and the 991.2 GT3 were compared with our renders. Caveats: octave ambiguity was decided by plausibility, the trackers have a bias of about 15 points on the between-harmonic share, and exterior clips carry Doppler and distance, so targets are approximate and relative structure matters more than absolute levels. Our renders are measured as mono (L+R): the left channel alone carries the stereo side signal (bank A minus bank B, order 3 for a V12) and overstates order 3 by 10-30 dB, which an earlier comparison did. The changes (each its own commit; the M4, LFA and Carrera GT render bit-identically in all scenarios with `std` and `i4hk`):
- F12 order 3 (rpm/20, half the firing rate): real -13 to -20 dB of the firing line from idle to 4,500 rpm, ours was -6 to -12 (L+R). `fire.deg` 65/55 -> 62/58: now -20, -13, -18 and -19 dB at 1,000, 2,000, 3,500 and 4,400 rpm.
- Non-firing orders of the V12s: real orders 1, 2, 4 and 5 sit at about -15 to -20 dB of the firing line, ours at -30 to -45. Cylinder gain now follows the firing position j as 1 + a cos(2π·2j/12) + b cos(2π·4j/12 + φ) (no bank-parity term, so order 3 does not rise); F12 a/b 0.03/0.05 (±6.5 %), Vanquish S 0.035/0.03 (±5 %; more order 2 would put 23 Hz at 700 rpm idle above the i4hk check's -25 dB below 25 Hz), V12 Vantage S 0.045/0.04 (±8 %); runner spread doubled (±0.09 ms). ## Output profiles (speaker system)

`EngineCore.outputs()` holds the output chain settings, sent with `msg({ k: 'out', o })` (same fade as a car switch) and picked under Innstillinger as "Lydanlegg". `std` is the old chain (DC block 26 Hz, +4 dB at 105 Hz, 7.5 kHz roll-off, limiter at 0.86) and is the engine's built-in default, so the M4 regression gate is unchanged. `i4hk` ("BMW i4 M50 Harman Kardon") is the page's default for this owner: two first-order high-passes at 18 Hz for a clean bottom, +3 dB at 60 Hz (Q 0.8) for weight around the firing fundamentals and the 62 Hz driveline thump, roll-off moved to 12 kHz, level 0.6 before the limiter and a ceiling of 0.53 (-5.5 dBFS) so that peaks stay at or below -5.5 dBFS outside the tunnel and below about -0.5 dBFS with the tunnel reverb (the page's soft clipper starts at 0.8; in the worst tunnel test it touches under 0.005 % of samples), and stereo width × 0.6 because the car's DSP upmixes. It is about 4 dB quieter than `std`; the owner turns up the car volume.
Measured (test.js, worst case: Bane, full burble, limiter): peaks -5.5 to -8.2 dBFS (-0.5 to -4.1 dBFS in the tunnel), energy below 25 Hz at idle -26 dB (M4, from its cycle-to-cycle variation, left as is) and -31 to -34 dB (V12s) of the total, side/mid -17 to -21 dB.

Treble above 8 kHz (`lp2`): an optional second one-pole low-pass in the output profile (`lp2`, Hz; absent or 0 = off, so `std` is unchanged). `i4hk` uses 10 kHz. Measured against a 192 kHz render of the same drives (decimated to 48 kHz; the reference copy scales the per-sample white noise by sqrt(sr/48000) so it keeps its 48 kHz density, without which the 192 kHz render is 4-5 dB darker for that reason alone, which is why an earlier comparison saw 6-12 dB): the 48 kHz i4hk output had +2.9 to +4.1 dB too much energy in 8-20 kHz (+4 to +7 dB in 16-20 kHz, from one-pole filters flattening near Nyquist and folded noise); with `lp2` the excess is +0.3 to +1.7 dB (8-20 kHz down about 2.5 dB, 16-20 kHz about 4 dB), 4-8 kHz loses 0.8 dB (it was 1.2-1.5 dB above the reference) and 2-4 kHz 0.2 dB, for every car. Above 16 kHz the test drive now sits at -30 to -38 dB of the total. 9 kHz would cost 1.1 dB in 4-8 kHz. Only the owner's ears in the car can judge the EQ target, the low end and whether the level suits the car's own processing.

### Drive log ("Kjørelogg")

Innstillinger › Kjørelogg: "Ta opp kjøring" (`rec`, off by default) records while the sensors run; "Ta med posisjon (GPS-koordinater)" (`recPos`, off by default) adds latitude/longitude to each GPS fix, and nothing else ever stores the position. "Last ned logg" opens the share sheet on a touch device when `navigator.canShare({ files })` allows it (Save to Files, Messages), otherwise it downloads `lydmotor-logg-YYYYMMDD-HHMM.json`; "Slett logg" needs a second tap within 3 s. The status row shows "REC m:ss".
- Recording: columns in typed arrays allocated once (about 4.6 MB) when recording is first switched on; a sample row is written from `fuse()` at most every 100 ms (so 10 Hz while motion or the GPS fallback runs), a GPS row at every fix, events as they happen. Cap: 2 hours of rows (72,000), 14,400 GPS rows, 20,000 events; when full, the oldest half is dropped. New rows go to IndexedDB (database `lydmotor-logg`, store `chunks`, one record per 30 s holding typed-array slices) every 30 s and when the page is hidden; on load the chunks are read back and recording continues (event `load`). Every storage call is wrapped; without IndexedDB the log lives in memory only.
- Format (JSON, `format: 'lydmotor-logg'`, `version: 1`): `build` (content hash), `created`, `ua`, `hz` (10), `gpsLag` (ms the fusion assumes, 1000), `durMs`, `pos`, `state` (`car`, `out`, `mode`, `ex`, `vc`, `cfg` = the stored settings, `fwd` = learned forward axis, `bias`, `gBase`), and three tables, each an object of equal-length arrays (`null` = not available):
  - `s` (samples): `t` (ms since 1970: wall clock at page load plus `performance.now()`), `aRaw` (m/s², `accelerationIncludingGravity` · forward axis, so it includes the slope), `aLin` (m/s², the gravity-separated horizontal acceleration · forward axis minus the learned bias, exactly what the fusion integrates; `null` before calibration), `rot` (°/s, rotation-rate magnitude), `vEst` (m/s, fused speed), `thr`, `brk` (0-1, the estimates sent to the engine), `dir` (1 forward, -1 reverse), `grade` (slope fraction), `held` (1 while the jolt guard freezes throttle and brake), `rpm`, `gear`, `load`, `vEng` (engine telemetry; `vEng` is the simulated speed in m/s), `volDb` (road-noise boost in dB).
  - `gps`: `t` (receive time, same clock as `s.t`), `ts` (the fix's own `timestamp`), `spd` (m/s as reported; the iPhone gives -1 when unknown), `acc` (m), `hdg` (° or `null`: heading availability), `good` (1 if the fusion used the fix), `lat`, `lon` (`null` unless "Ta med posisjon" was on).
  - `ev`: `[t, kind, value]`. Kinds: `load` (page loaded with recording on: build, car, output, exhaust, road-noise step), `rec` (started, with the same metadata, or 0), `start` ("drive AudioWorklet" and so on), `mode`, `car`, `out`, `ex`, `tun` (reason or 0), `audio` (`AudioContext.state`, plus `/keep-pause` when the silent track is paused; `interrupted`/`suspended`/`running` show iOS interruptions), `wake` (1/0), `vis` (1 visible, 0 hidden), `mute` (1/0, Media Session), `gpsErr` (code), `pos`, `eng` (`up 2>3`, `blip 4>3`, `kick 6>4`, `lim`, `deny`, `lift`).
- `src/loganalyze.js` prints: rows, sample interval, GPS fixes, accuracy and heading share; the GPS delay by cross-correlation (the change in GPS speed between consecutive fixes against the change of a signal over the same window shifted back by 0-3 s; best Pearson r with parabolic refinement), once against the integrated accelerometer (`aLin`, trapezoid rule, windows with missing samples or jolts skipped) and once against the fused speed; the speed error (`vEst` at the fix time minus the delay, minus the GPS speed: mean, rms, 95th percentile, max); the throttle distribution while moving (share under 0.05 = lift) and the brake share; gear shifts and hunting (a shift followed by one the other way within 3 s, also per hour of driving); direction changes and time in reverse; event counts. Unit test (`sensortest.js`): the synthetic drive through the real fusion with recording on, GPS 1.0 and 1.5 s late: accelerometer estimate 0.92 and 1.43 s (it reads about 0.05-0.1 s short), fused-speed estimate 0.86 and 1.48 s (pulled towards the 1.0 s the fusion assumes, so trust the accelerometer figure when they differ), speed rms 0.39 m/s; the log also survives a reload through IndexedDB.

### Offline: service worker

`build.py` writes `sw.js` with `VERSION` = the first 12 hex digits of SHA-256 over the built page (before the hash is inserted), `src/sw.js` and every precached file, and puts the same value into `index.html` as `BUILD`. Precache (cache `lydmotor-<VERSION>`): `index.html`, `manifest.webmanifest`, `apple-touch-icon.png`, `favicon.png`, `icon-192.png`, `icon-512.png`, `icon-maskable-512.png`, all relative to the worker, so it works under `/Fun-stuff/m4-lydmotor/` (scope `./`).
- Fetch: only same-origin GET requests inside the scope. Navigations and `index.html`: network first (the fresh copy is stored), the cached copy after 3 s or on a network error. The listed icons and the manifest: cache first. Everything else, and every other origin (the OpenStreetMap lookup), is never intercepted or cached.
- Updates: no `skipWaiting` on install, so a new worker takes over on the next launch. The page registers only on https or localhost (try/catch; the claude.ai artifact copy simply runs without it), checks for an update when it returns to the foreground (at most once an hour), and asks a waiting worker for its version: if it equals the page's `BUILD` (the page already came fresh from the network), the worker takes over silently; otherwise the status row shows "Ny versjon klar", and only a tap activates it and reloads. The page never reloads by itself. Activation deletes the old `lydmotor-*` caches.
- Busting the cache: any change to a source file, the icons or the manifest changes `VERSION` on rebuild; commit `sw.js` together with `index.html`. Tested in headless Chrome: precache content, an offline reload starts test mode, icons come from the cache, a cross-origin request fails offline (the worker does not serve it), a new build (new hash in page and worker) replaces the cache silently, and a worker newer than the open page shows the chip; a tap reloads into it.

### Media Session (lock screen, CarPlay "Now Playing")

On start: `navigator.mediaSession.metadata` = title "Lydmotor", artist = the car's full name, album "Lydmotor", artwork `icon-192.png` and `icon-512.png`; updated on every car switch. `playbackState` "playing"; handlers `play` (unmute), `pause` and `stop` (mute). Muting ramps a master GainNode after the soft clipper to 0 (time constant 80 ms) and back; the AudioContext, the silent looping `<audio>` element (which is what iOS shows as Now Playing) and the watchdog in `sysTick` keep running, so resuming is instant. The status row shows "Dempet · trykk for lyd"; tapping it also unmutes. Checked in Chrome: metadata values, handler wiring, the mute ramp, `playbackState`. Whether iOS shows it on the lock screen and in CarPlay, and whether the CarPlay pause button reaches the handler, needs a real iPhone.

### Road-noise volume ("Veistøy", setting `vc`)

Innstillinger › Veistøy: Av / Lav / Normal (default) / Høy = +0 / 2 / 3.5 / 5 dB at 120 km/h and above, linear in speed from 0 dB at standstill, smoothed with a 1 s time constant (63 % after 1 s), updated four times a second in `sysTick` and sent as `cfg vol` (volume × boost; the engine applies `vol` after its limiter, so output peaks are volume × the output ceiling). Only in drive mode with sensors on; test mode decays to 0 dB.
- Cap: the effective volume never exceeds max(volume, `PEAK_MAX` / (ceiling × (`TUN_PK` in a tunnel, else 1))), with `PEAK_MAX` 0.79 (-2.05 dBFS; the soft clipper starts at 0.8) and `TUN_PK` 1.9, and it is never below the user's own volume. For i4hk (ceiling 0.53, -5.5 dBFS) that allows up to ×1.49 (+3.5 dB at volume 1); in a tunnel (worst case 0.53 × 1.745 = 0.92) volumes above 0.785 get no boost; with `std` (ceiling 0.86) volumes above 0.92 get none.
- Verified offline in `sensortest.js` with the page's own graph in an OfflineAudioContext (soft clipper bypassed so the peak is measured before it): every car, Bane, full burble, manual box into the limiter, lift-off pops, i4hk (plus the M4 on `std`), dry and tunnel at Tunnelklang 1.5. Peak / ceiling at volume 1: dry 0.74-1.000 (the limiter holds the ceiling), tunnel 1.32 (F12) to 1.745 (LFA, and the M4 on `std`). With the largest boost (Høy at 200 km/h) and volume 0.2-1.0 the worst peak where a boost applies is -2.05 dBFS, and no case exceeds the peak it had without the boost. Mapping checks: +3.5 dB at 120 km/h, +1.75 at 60, 63 % after 1 s, volume 0.8 -> 1.196 at 120 km/h. Whether the amounts suit the i4's cabin is for the owner's ears.

### Gauge frame rate

30 fps as before; 15 fps after 20 s of standing still (simulated and fused speed under 0.1 m/s, no pedal or brake, no shift, rpm below idle + 250, no start sweep); back to 30 at once on movement, a touch or a key; nothing is drawn while the page is hidden. The needle smoothing still runs every animation frame. Headless measurement: 30.0 / 15.0 / 30.0 / 0 frames per second (moving / still over 20 s / after a tap / hidden). The battery effect on an iPhone is not measured.

### Settings, per-car presets, export and import

Stored in `localStorage` key `lydmotor` (the old key `m4csl` is still read, then removed): `vol`, `bur`, `tunAmt`, `idle`, `tunGps`, `tunMap`, `ex`, `car`, `out` (unchanged names), plus `vc` (0-3, default 2), `rec`, `recPos` and `cars` (`{ carId: { vol, bur, ex } }`). Volume, exhaust mode and burble are remembered per car: switching stores the current values under the old car and applies the new car's, or keeps the current ones if the car has none yet (so older saved settings migrate by being inherited). The global `vol`/`bur`/`ex` always mirror the selected car. Every read goes through `cleanCfg()`: unknown keys and unknown car ids are dropped, numbers clamped (vol and bur 0-1, tunAmt 0-1.5, ex and vc rounded into range), wrong types ignored; it never throws. Innstillinger › Innstillinger på fil: "Eksporter" (share sheet or download, `{ format: 'lydmotor-innstillinger', version: 1, build, settings }`) and "Importer" (a file input; up to 256 kB, validated the same way and applied live: car, output, exhaust, road-noise step, recording; a bad file only shows a message). The calibration (`m4cal`) is not exported, because it belongs to the phone's mount.

### Messages and robustness (Norwegian, never blocking)

- Motion permission refused: the drive panel says so, keeps the retry button ("Prøv igjen") and explains that a refused answer needs the tab closed and reopened; the generic "Mangler …" text after 4.5 s no longer overwrites it.
- GPS errors: denied (where to allow it in iOS Settings, then reload), unavailable (Location Services), timeout ("Venter på GPS-signal …" instead of "Ingen signal"); each is logged as `gpsErr`.
- Audio start: if no AudioContext can be created, the start screen says why and stays up; if neither the worklet nor the ScriptProcessor fallback starts, the latency line says so instead of showing a latency.

### Not verified here (needs the owner's iPhone)

The service worker in iOS Safari and in the home-screen app (iOS may evict caches after weeks without use), the update chip on iOS, Media Session on the lock screen and in CarPlay (and whether CarPlay's pause/play reach the handlers), the share sheet with a JSON file (Files, Messages), IndexedDB persistence and quota in Safari (and that a two-hour log survives a crash), the CPU cost of recording at 10 Hz, the battery saving of 15 fps, and whether the road-noise amounts suit the car.
